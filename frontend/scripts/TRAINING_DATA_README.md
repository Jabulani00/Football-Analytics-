# Match-prediction training data

`training_data.csv` is generated by [`exportTrainingCsv.ts`](./exportTrainingCsv.ts):

```bash
cd frontend
npx tsx scripts/exportTrainingCsv.ts 16 100 ../training_data.csv
#                                     │  │   └ output path
#                                     │  └ max pages (×250 fixtures)
#                                     └ months of history to pull
```

It pulls finished fixtures across **many leagues** from the OddAlerts proxy, walks
each team's matches in time order, and writes **one row per match**. Every feature
is **point-in-time** — computed only from games played **before** that match — so
there is **no target leakage**. The stat names match the app's own vocabulary.

## Columns

### Match details (identifiers — drop before training, keep `competition`/`date` for splitting)
`fixture_id, date, competition_id, competition, season, home_id, home_team, away_id, away_team`

### Pre-match form features (these are your X / inputs)
Four blocks, each the same 18 stats over the team's recent games **before** this match:

| Prefix | Meaning |
|--------|---------|
| `h_ovr_*` | Home team — last 10 games, all competitions |
| `h_home_*` | Home team — last 6 **home** games |
| `a_ovr_*` | Away team — last 10 games, all competitions |
| `a_away_*` | Away team — last 6 **away** games |

The 18 stats (our terminology):
`n` (games in the window), `gf_avg`, `ga_avg`, `goals_avg`, `ppg`,
`scored_pct`, `conceded_pct`, `clean_sheet_pct`, `failed_to_score_pct`, `btts_pct`,
`over_1_5_pct`, `over_2_5_pct`, `over_3_5_pct`, `win_pct`, `draw_pct`, `loss_pct`,
`scored_1h_pct`, `conceded_1h_pct`.

### Targets (pick ONE to predict — these are your y / labels)
| Column | Task | Type |
|--------|------|------|
| `y_result` | Home / Draw / Away | 3-class |
| `y_home_win`, `y_draw`, `y_away_win` | each outcome | binary |
| `y_btts` | both teams to score | binary |
| `y_over_1_5`, `y_over_2_5`, `y_over_3_5` | goal lines | binary |
| `y_ht_btts`, `y_1h_result` | first-half markets | binary / 3-class |
| `y_home_goals`, `y_away_goals`, `y_total_goals`, `y_goal_diff`, `y_2h_total` | goal counts | regression |

**Always drop every other `y_*` column (and the identifiers) from X** when you train
one target — otherwise you leak the result.

## Colab vs Kaggle — recommendation

**Use Kaggle** for this. Why:
- Upload `training_data.csv` once as a **Dataset**; every notebook version re-attaches it automatically (no re-uploading to Google Drive each session).
- Free, persistent compute (CPU is plenty for tabular data; 30 h/week GPU if you ever want it), and notebooks are versioned, so your training runs are reproducible.
- XGBoost / LightGBM / scikit-learn are pre-installed.

Use **Colab** if you prefer Google Drive integration or want to paste a quick throwaway cell — it works fine too, you just re-upload the CSV (or mount Drive) each session.

Either way the code below is identical.

## Starter notebook (XGBoost, `y_over_2_5`)

```python
import pandas as pd, numpy as np
from xgboost import XGBClassifier
from sklearn.metrics import roc_auc_score, accuracy_score, log_loss

df = pd.read_csv("training_data.csv")           # Kaggle: /kaggle/input/<your-dataset>/training_data.csv

TARGET = "y_over_2_5"
ids = ["fixture_id","date","competition_id","competition","season",
       "home_id","home_team","away_id","away_team"]
targets = [c for c in df.columns if c.startswith("y_")]
X = df.drop(columns=ids + targets)
y = df[TARGET].astype(int)

# Time-based split (train on the past, test on the most recent 20%) — never shuffle football.
order = df["date"].argsort().values
cut = int(len(df) * 0.8)
tr, te = order[:cut], order[cut:]

model = XGBClassifier(n_estimators=400, max_depth=4, learning_rate=0.05,
                      subsample=0.9, colsample_bytree=0.8, eval_metric="logloss")
model.fit(X.iloc[tr], y.iloc[tr])
p = model.predict_proba(X.iloc[te])[:,1]
print("AUC", roc_auc_score(y.iloc[te], p),
      "ACC", accuracy_score(y.iloc[te], p>0.5),
      "logloss", log_loss(y.iloc[te], p))

# For y_result (3-class) use objective="multi:softprob" and LabelEncoder on y.
```

Tips: predict one market at a time; compare against the base rate (e.g. ~55 % of
matches go Over 2.5, so beat that); and keep the **time split** — a random split
inflates the score because future form leaks into training.
